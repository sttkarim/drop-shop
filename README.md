# STT Drop — Telegram-бот + Mini App для дропшиппинга

Telegram-бот со встроенным **Mini App**: каталог товаров с фото и актуальными
остатками по размерам, оформление заказов (транспортная компания + трек-номер),
автоматический подсчёт остатков и админ-доступ к изменению наличия.

Сценарий: продавцы выставляют ваш товар на Авито → покупатель заказывает →
продавец открывает Mini App, проверяет наличие размера и оформляет заказ.

---

## Возможности

**Продавец (дропшиппер):**
- 🛍 каталог: карточки с главным фото, ценой и бейджем наличия;
- 🔍 карточка товара: до 20 доп. фото (галерея), описание, остатки по каждому размеру;
- 📦 заказ: выбрать размер → транспортная компания (СДЭК, Яндекс маркет, Авито, 5post, Почта России или свой вариант) → трек-номер;
- 📋 «Мои заказы» со статусами.

**Админ:**
- ➕ добавить товар (главное фото + до 20 доп. фото, размеры и начальное наличие);
- ⚙️ изменить остатки любого размера вручную;
- 🧾 все заказы + смена статуса (новый → подтверждён → отгружен → выполнен).

**Автоподсчёт остатков:** админ задаёт начальное наличие один раз; при каждом
заказе бот сам списывает количество. Если остатка не хватает — заказ не проходит.

---

## Архитектура

```
Telegram
  │  бот (python-telegram-bot): кнопка «Открыть каталог» (web_app)
  ▼
Один процесс: Starlette (Mini App + REST API) + Telegram-бот
  │
  └── SQLite (товары, фото, размеры, остатки, заказы)
```

- `app/` — бэкенд: `main.py` (приложение), `db.py`, `security.py` (проверка подписи initData), `api/routes.py`, `bot/handlers.py`.
- `static/` — Mini App (HTML/CSS/JS).
- `static/uploads/` — загруженные фото товаров.

## Быстрый старт (локально)

### 1. Бот и токен
Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`), получите токен.
Узнайте свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)).

### 2. Настройка
```bash
cd dropapp
cp .env.example .env
# впишите BOT_TOKEN и ADMIN_IDS
```

### 3. Установка и запуск
```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 4. HTTPS для Mini App (обязательно)
Telegram открывает Mini App только по HTTPS. Для локальной разработки используйте
туннель, например **cloudflared**:

```bash
cloudflared tunnel --url http://127.0.0.1:8000
# в выводе появится https://xxxx.trycloudflare.com
```

Впишите этот адрес в `.env`:
```
WEBAPP_URL=https://xxxx.trycloudflare.com
```
и перезапустите сервер. Теперь кнопка «🛍 Каталог» в боте откроет Mini App.

> Для продакшена подойдёт любой хостинг: Railway / Render / Fly.io / VPS с HTTPS
> (nginx + certbot). Просто запустите `uvicorn` и укажите публичный `WEBAPP_URL`.

## Хостинг (постоянный)

Для постоянной работы нужен сервер, который не спит (24/7), и HTTPS-адрес.
Два проверенных пути.

### Путь A — VPS + Docker (рекомендую, дёшево и надёжно)

Нужен: недорогой VPS (Hetzner/DigitalOcean/любой) и **домен** (можно дешёвый, ~200 ₽/год).
Всё уже подготовлено: `Dockerfile`, `docker-compose.yml`, `Caddyfile` — Caddy сам выпустит
HTTPS-сертификат.

1. Купите VPS (например, Hetzner ~€4/мес, Ubuntu 22.04/24.04) и привяжите домен:
   в панели регистратора создайте A-запись `shop.example.com → IP_вашего_VPS`.
2. Подключитесь к VPS по SSH и установите Docker:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. Загрузите проект на VPS (например, `git clone <ваш-репозиторий>` или через SCP).
4. В файле `.env` на сервере заполните:
   ```
   BOT_TOKEN=...
   ADMIN_IDS=...
   DOMAIN=shop.example.com
   ```
5. Запустите (одной командой):
   ```bash
   docker compose up -d --build
   ```
6. Через минуту Mini App будет доступен по `https://shop.example.com` — впишите этот
   адрес в `WEBAPP_URL` и перезапустите: `docker compose up -d`.

База данных и фото хранятся в Docker-томе `shopdata` и **не теряются** при
перезапуске. Обновление кода: `git pull && docker compose up -d --build`.

> Бот работает через long-polling, поэтому запускайте **ровно один экземпляр**
> (не масштабируйте горизонтально).

### Путь B — управляемый хостинг (Railway / Render), без домена

Проще в первые минуты (даёт HTTPS-адрес вида `xxx.up.railway.app`), но для 24/7
и хранения файлов нужен платный тариф + подключённый «volume» (постоянный диск).

1. Загрузите папку `dropapp/` в GitHub.
2. В Railway/Render создайте сервис из репозитория (команда запуска — см. `Procfile`).
3. Задайте переменные `BOT_TOKEN`, `ADMIN_IDS`, `WEBAPP_URL` (= адрес сервиса).
4. Подключите **volume** и укажите в переменных `DB_PATH=/data/shop.db`, `UPLOADS_DIR=/data/uploads`.

> На бесплатном тарифе приложение «засыпает» после простоя — бот будет пропускать
> сообщения. Для реального магазина выбирайте тариф без сна.

## Формат ввода размеров (в админке)

В поле «Размеры и остатки» перечислите через запятую, количество через двоеточие:
```
S:5, M:2, L:0
41:3, 42:0, 43:7
```

## Тесты

```bash
cd dropapp

```
Проверяют БД, подпись initData, каталог, оформление заказа и автоподсчёт остатков.

---

## Заметки

- Подпись `initData` от Telegram проверяется на сервере (HMAC-SHA256) — заказы и
  изменения остатков не подделать.
- Роль админа определяется по `ADMIN_IDS` в `.env`.
- Если Telegram у провайдера заблокирован/замедлен — задайте `PROXY_URL` (socks5/http).
